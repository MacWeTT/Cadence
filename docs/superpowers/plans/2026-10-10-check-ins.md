# Check-ins and the Today Page (Milestone 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Today page where the user ticks habits off for any day up to today: optimistic toggles, streak and weekly-progress tags, day navigation for backfill, and the empty states.

**Architecture:** Two small pure domain helpers decide what is listed and what weekly progress to show. A Postgres function enforces the tick rules. A pure server module turns database rows into the rows the page shows; a client component renders them with optimistic updates and a server action.

**Tech Stack:** Next.js 16 (Cache Components), React 19 (`useOptimistic`), shadcn/ui, Supabase, zod, Vitest, pgTAP, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-10-check-ins-design.md` (read first; it builds on the two earlier specs). Work on branch `feat/check-ins`; it lands as a PR into `develop`, never a direct merge.

## Global Constraints

- The constraints of the earlier plans still apply: TypeScript only, dates as `YYYY-MM-DD`, domain code pure, `connection()` before Supabase auth calls, session reads behind `<Suspense>`, RLS on every table, shadcn components in `src/components/ui/`, errors as `{ ok } | { ok: false, error }` and never thrown for expected failures. Read `node_modules/next/dist/docs/` before using an unfamiliar Next API (`AGENTS.md`).
- Tick rules (spec section 4): the day is not after today in the user's timezone, not before the habit's start date, and the habit is not archived. One row per habit per day.
- User-facing sentences are never built by concatenating parts, and dates and numbers go through `Intl` helpers (`formatCalendarDate`).
- Streaks show only when viewing today. The viewed day is the `date` search parameter; anything missing, malformed or in the future means today.
- Contrast: text meets 4.5:1 in both themes (use `text-ink-muted` only for secondary text, `text-danger` for errors).
- Every task ends with lint, typecheck and its tests passing, then a commit ending with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Never claim a command passed without running it. The e2e tests need Docker with the local Supabase running and `SUPABASE_SERVICE_ROLE_KEY` in `.env.local`.

## Review Focus

1. A double tap on one row sends one request and creates one completion (Task 5).
2. Ticking yesterday from `?date=` persists after a reload; a future or garbage `date` falls back to today without an error (Task 6).
3. A habit created today is not listed on earlier days; one with an earlier start date is listed from that date on (Tasks 1, 6).
4. An archived habit is not listed; after a restore it is listed again with its earlier ticks (Tasks 1, 5).
5. A weekly habit at its goal shows "Goal met", not "4 of 3", and unticking one shows "2 of 3" again (Tasks 1, 3, 5).
6. A failed save reverts the row and its section and shows the toast (Task 5).

### Task 1: Domain helpers `isListedOn` and `weekProgress`

**Files:** Create `src/domain/listing.ts`, `src/domain/listing.test.ts`. Modify `src/domain/index.ts`.

**Interfaces:**
- Consumes `HabitData`, `Ctx`, `scheduleFor`, `isPaused`, `weekStart`, `weekEnd`, `addDays`.
- Produces `isListedOn(h: HabitData, date: CalendarDate, ctx: Ctx): boolean` and `weekProgress(h: HabitData, date: CalendarDate, ctx: Ctx): { done: number; target: number; goalMet: boolean } | null`.
- Rules: `isListedOn` is false for a date after `ctx.today`, before `startDate`, with no schedule in effect on the date, or when the habit is archived right now (any pause with `to === null`); a date inside a closed pause is listed only if it was ticked. `weekProgress` is `null` unless the schedule in effect on the date (using `max(weekStart(date), startDate)`) is weekly; otherwise `done` counts ticks from `max(weekStart, startDate)` to `min(weekEnd, today)`, `target` is the weekly target, and `goalMet` is `done >= target` (ticks above the target still count in `done`).

### Task 3: Today view mapping (pure)

**Files:** Create `src/server/today-view.ts`, `src/server/today-view.test.ts`.

**Interfaces:**
- Consumes the domain (`HabitData`, `Pause`, `Schedule`, `isListedOn`, `weekProgress`, `currentStreak`, `weekStart`, `toCalendarDate`), `habit-view` row types (`HabitRow`, `ScheduleRow`, `toSchedule`), `ColorKey`.
- Produces `type PauseRow = { habit_id: string; archived_on: string; restored_on: string | null }`; `toHabitData(habit: HabitRow, schedules: ScheduleRow[], pauses: PauseRow[], completionDates: string[]): HabitData`.
- Produces `type TodayRow = { id: string; name: string; icon: string; color: ColorKey; ticked: boolean; streak: { unit: 'day' | 'week'; count: number } | null; week: { done: number; target: number; goalMet: boolean } | null }` and `type TodayView = { todo: TodayRow[]; done: TodayRow[]; hasHabits: boolean }`.
- Produces `buildTodayView(habits: { habit: HabitRow; data: HabitData }[], date: CalendarDate, ctx: Ctx): TodayView` (lists habits where `isListedOn`; `ticked` is whether the date is in `completions`; `streak` only when `date === ctx.today` and the count is above 0; `week` from `weekProgress`; rows keep creation order; `hasHabits` is true when at least one non-archived habit exists at all, regardless of the date).
- Produces `parseDateParam(value: string | string[] | undefined, today: CalendarDate): CalendarDate` (a valid date not after today, else today) and `earliestDate(habits: { data: HabitData }[], today: CalendarDate): CalendarDate` (the earliest `startDate` among non-archived habits, or `today` when there are none).
